# KMMOM UI 测试技能使用说明

## 1. 技能定位

`kmmom-ui-test-generator` 是用于 KMMOM/MOM 系统 UI 遍历和控件采集的测试辅助技能。

它的核心作用是：

- 自动遍历指定模块或页面；
- 识别页面上的按钮、筛选项、下拉框、输入框、日期控件、表格控件、页签、弹窗/抽屉入口；
- 对安全控件进行点击、展开、输入/清空；
- 对高风险控件只记录，不执行最终业务动作；
- 输出 Excel 形式的控件清单、点击记录、页面汇总和异常线索；
- 必要时将点击记录转换为 MeterSphere 导入格式测试用例。

一句话说明：

> 这个技能适合做 UI 控件盘点、页面覆盖检查和异常线索收集，不适合直接替代人工测试或直接判定缺陷。

## 2. 适用场景

推荐使用场景：

- 新模块上线前，快速盘点页面控件；
- 大版本升级后，检查页面是否能正常打开；
- 回归测试前，补充按钮、筛选项、下拉框等覆盖信息；
- 对指定模块生成界面按钮点击测试记录；
- 整理页面控件清单，辅助补充测试点或测试用例；
- 初步收集页面报错、登录失效、接口失败、空白页等异常线索。

不推荐使用场景：

- 直接在生产环境执行危险操作；
- 直接把异常汇总作为缺陷清单；
- 自动化代替人工业务流程测试；
- 对复杂弹窗页面进行无人值守高速全量点击；
- 对保存、提交、删除、审核、发布等最终业务动作进行自动确认。

## 3. 使用前准备

使用前请确认：

- KMMOM/MOM 系统地址可访问；
- Chrome 浏览器已打开；
- 当前账号已登录系统；
- 当前账号具备目标模块菜单权限；
- 测试环境允许自动化遍历；
- 明确本次遍历范围，是单模块、多个模块，还是全模块；
- 默认开启安全模式，不执行会改变业务数据的最终动作。

建议优先从单模块开始，不建议第一次就直接跑全模块。

## 4. 推荐使用方式

可以这样给 Codex 下指令：

```text

采集页面内所有按钮、筛选控件、下拉控件、输入框、日期控件、表格控件和弹窗入口，
生成界面按钮点击测试记录表和完整控件清单。
执行过程中开启安全模式，不执行保存、提交、删除、导出、审核等最终业务动作。
若出现系统报错、接口异常、登录失效、页面无法访问等情况，记录异常提示和截图。
无需生成测试用例。
```

适合大版本升级后的整体摸底。

可以这样给 Codex 下指令：

```text
基于 KMMOM UI 测试 skill，遍历 MOM 系统全模块全部页面，
采集所有按钮、筛选控件、下拉控件、输入框、日期控件、表格控件、页签和弹窗入口，

异常结果仅作为复核线索，不直接作为缺陷结论。
```

全模块遍历耗时较长，建议有人观察执行过程，发现登录失效、网络中断、系统明显报错时及时暂停复核。

### 4.3 只列页面，不执行点击

适合先确认模块页面范围。

```text
基于 KMMOM UI 测试 skill，仅列出【模块名称】模块下可遍历的菜单页面，不执行点击操作。
```

## 5. 安全边界

默认安全原则：

- 可以点击普通按钮、展开筛选项、展开下拉框、打开弹窗、关闭弹窗；
- 可以输入测试文本并清空；
- 可以读取页面提示、弹窗文本、toast 信息；
- 不执行保存、提交、删除、导出、下载、发布、下发、审核、通过、驳回等最终业务动作；
- 对高风险控件只记录可见性、启用状态、风险说明和预期结果。

正常防误操作弹窗不应作为异常，例如：

```text
删除后将无法恢复，确定要删除该记录吗？ 取 消 确 定
```

这类提示属于正常确认弹窗，应记录为正常确认或风险提示，不应直接归为系统异常。

## 6. 输出文件说明

常见输出包括：

- 完整控件清单；
- 界面按钮点击测试记录表；
- 异常汇总；
- 执行摘要；
- 分模块执行记录；
- 异常截图；
- 必要时生成 MeterSphere 导入测试用例。

推荐查看顺序：

1. 先看执行摘要，确认页面数、记录数、异常数；
2. 再看完整控件清单，确认控件采集覆盖情况；
3. 再看界面按钮点击测试记录表，查看具体控件响应；
4. 最后看异常汇总，逐条人工复核是否为真实问题。

## 7. 异常结果如何复核

异常汇总不是缺陷清单，只是异常线索。

复核时建议分为以下几类：

| 类型 | 处理建议 |
| --- | --- |
| 系统明确报错 | 单页复现后可考虑提缺陷 |
| 接口失败、服务异常 | 结合日志和网络请求复核 |
| 登录失效 | 判断是否执行时间过长或会话策略导致 |
| 网络连接重置 | 先排除环境和网络问题 |
| 正常业务校验 | 判断触发位置是否合理 |
| 删除/提交确认弹窗 | 通常是正常防误操作提示 |
| 页面内容大段重复 | 多数可能是弹窗或页面残留 |
| Runtime.evaluate、坐标元素未找到 | 多数可能是自动化执行问题 |
| 点击后路由跳转 | 判断是否符合页面设计，不直接算异常 |

复核原则：

- 能人工稳定复现的，才进入缺陷判断；
- 只在自动化记录中出现、人工无法复现的，先标记为待复测；
- 弹窗残留、页面未加载完成、坐标失效导致的问题，不直接提缺陷；
- 正常确认弹窗不归类为系统异常。

## 8. 常见问题

### 8.1 为什么异常汇总不能直接当缺陷？

因为自动遍历过程中可能遇到页面加载慢、弹窗未关闭、登录过期、坐标失效等情况。这些问题可能污染后续记录，所以异常汇总只能作为复核线索。

### 8.2 为什么建议先跑单模块？

单模块更容易观察执行过程，也更容易判断异常是否真实。全模块遍历时间长，登录状态、网络状态和系统负载都会影响结果。

### 8.3 遇到弹窗怎么办？

正常弹窗应先关闭或取消，再继续下一步。不要在弹窗未关闭时继续点击页面其他按钮。

### 8.4 删除确认弹窗算异常吗？

不算。删除确认、取消/确定这类防误操作提示是正常业务保护机制。

### 8.5 技能可以生成测试用例吗？

可以，但建议先生成点击记录并人工复核，再决定是否转换为 MeterSphere 测试用例。默认推荐一页一个用例，页面控件作为步骤。

## 9. 推荐执行流程

推荐流程：

1. 确认测试环境和账号权限；
2. 选择一个模块试跑；
3. 生成点击记录和控件清单；
4. 人工检查异常是否可信；
5. 确认脚本节奏和页面状态稳定后，再扩大范围；
6. 多模块或全模块执行；
7. 汇总控件清单和执行记录；
8. 对异常线索进行人工复核；
9. 对确认可复现的问题再提缺陷；
10. 必要时转换 MeterSphere 测试用例。

## 12. 结论

KMMOM UI 测试技能适合帮助测试人员快速完成页面控件盘点、点击记录生成和异常线索收集。

它的最佳使用方式是：

> 自动化负责采集和记录，人工负责复核和判断。

控件清单和点击记录可以作为测试覆盖分析资料；异常汇总必须经过人工复核后，才能决定是否提缺陷。
